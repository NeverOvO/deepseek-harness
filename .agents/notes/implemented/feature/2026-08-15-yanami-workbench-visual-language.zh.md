# Agent Note: 八奈见工作台视觉语言

Status: implemented

## Problem

DeepSeek Harness 默认 Web 外壳以中性的产品界面为目标。当前部署需要形成具有辨识度的个人工作台视觉，同时不能为了换视觉而分叉 Agent Loop、工具运行时、Session 模型，或为各功能包重新建立一套 UI 体系。新的视觉处理还需要兼容现有浅色/深色外观偏好，以及各功能包通过语义主题变量消费样式的既有约束。

只换配色仍然不够。空白会话状态还需要真正表达“工作台”的产品模型：工作模式、任务驾驶舱、项目记忆和证据交付；而进入具体任务后，又应该继续保留现有对代码、工具、日志和长任务更友好的高密度执行界面。

## Decision

Web 部署统一命名为 **八奈见工作台 / Yanami Workbench**。视觉语言通过 `ui-theme` 新增的 `yanami-workbench.css` 样式层实现，并由 Web Shell 在基础设计色板之后加载。

共享视觉常量仍归 `ui-theme` 所有，并新增八奈见工作台专用的语义变量：藏蓝和晴空蓝作为主要识别色，半透明白色表面承担玻璃质感，薄荷绿作为辅助色，柠檬黄只用于少量强调。深色模式采用“夜间自习”变体，同时覆盖本层改写过的通用语义变量和八奈见专用变量，因此原有 Appearance 切换仍然有效。

`ui-layout` 与 `ui-sidebar` 只消费这些语义变量，不各自维护第二套色板。应用背景使用柔和的夏日渐变，三栏框架改为通透表面，侧栏把默认品牌字标替换为“八奈见工作台 / Yanami Workbench”，折叠栏使用 `八` 字标识。浏览器标题与 PWA 名称也统一为“八奈见工作台”。

空白会话阶段不再使用原来的默认 Hero，而是显示一个有边界的八奈见工作台 Dashboard。它展示规划中的五大协作模式（Do / Spec / Plan / Review / Ship）、任务驾驶舱、项目记忆、证据交付，以及一个克制的八奈见风格助手元素。真实的 Workspace 选择器和 Composer 仍由 `ConversationRoot` 在 Dashboard 下方持有，因此开始输入任务后会自然进入现有会话树，而不是另起一套任务运行时。

Dashboard 只在空白会话阶段出现。任务一旦进入实际对话，界面继续使用原来的高密度执行布局。这样既能让新会话真正像一个“工作台入口”，又不会在代码、日志、工具输出和 Diff 区域长期占用空间。

角色立绘不会作为全局满屏壁纸硬编码。角色元素应放在助手、空状态或工作台的有限区域中，以便后续替换素材时不让主应用布局依赖某一张具体插画。

## Alternatives considered

**分别修改每个功能包的视觉。** 不采用，因为这会在多个 CSS Module 中复制固定颜色，破坏主题所有权规则，也会显著增加未来同步上游时的冲突。

**直接重写整个 Web Shell 为独立 Dashboard。** 不采用，因为现有 Slot、Layout 与 Session 基础设施仍然有价值，而且进入实际任务后的执行界面本身很适合承载代码与工具输出。因此 Dashboard 只接管空白会话阶段，而不是替换整个执行界面。

**在每个活动会话中永久显示 Dashboard 卡片。** 不采用，因为这些卡片会与代码、日志、工具输出和 Diff 争夺横向与纵向空间。工作台结构应该出现在任务开始前；开始执行后，屏幕优先让给任务内容。

**把用户提供的角色图作为全屏壁纸。** 不采用，因为会降低信息区的文字对比度，使产品更像壁纸皮肤而不是工作工具，并让核心布局与某一张插画绑定。角色内容保留为可替换的有限区域层。

## Consequences

当前部署不仅获得独立、明确的视觉身份，也获得了结构上不同的空白会话首页，同时保留 DSH 的插件架构、布局语义、Composer 生命周期和浅色/深色外观偏好。上游功能包继续消费语义变量，因此无需各自维护私有色板也能自动继承新的工作台风格。

目前 Do / Spec / Plan / Review / Ship 卡片表达的是下一阶段要落地的协作模型，还不是运行时 Mode 状态的权威来源；在行为层真正接入之前不会把它们伪装成已经工作的控制器。任务驾驶舱、项目记忆和证据交付面板同样只承担产品框架展示，不伪造已经存在的数据能力。

目前八奈见视觉层属于部署级定制，而不是 Appearance 中可单独选择的主题：切换浅色或深色只改变八奈见工作台的对应配色变体，不会关闭这层覆盖。如果未来该仓库需要同时发布多个品牌工作台，应把这一层提升为注册主题/Profile，而不是继续堆叠全局部署样式。
